# 工程と成果物

必要な成果物とその粒度を、顧客の納品一覧や引き継ぐ人の仕事に合わせて選ぶ。各項目には対象版、現行仕様、確認状態、根拠を記す。

| 工程 | 作成する資料の例 | 追加で必要になる情報 |
|---|---|---|
| 企画・調達 | 企画書、開発計画、調達仕様 | 目的、契約範囲、当初予算・日程 |
| 要件定義 | 業務フロー、機能・非機能要件、受入条件 | システム外の作業、例外、性能や復旧の目標 |
| 基本設計 | 画面遷移、帳票、外部連携、権限、バッチ | 本番設定や連携相手との合意 |
| 詳細設計・実装 | 処理仕様、テーブル定義、データ更新、ビルド手順 | 制約・失敗時の動き、設計理由 |
| テスト・受入 | 単体・結合・総合・受入の仕様と結果 | 実施環境・実行記録、検収判断 |
| 移行・リリース | データ移行、切替・切戻し計画、実施報告 | 停止可能時間、切替判断、移行実績 |
| 運用・保守・廃棄 | 操作・監視・復旧手順、引継ぎ、廃棄計画 | 担当者、保持期限、訓練や廃棄の記録 |
| 全工程 | 要求対応表、課題・変更・レビュー記録 | 過去の決定と今回の判断の根拠・日付 |

工程と役割の参考にIPAの[共通フレーム2013](https://www.ipa.go.jp/publish/secbooks20130304.html)を使う。聞き取り、要求・実装・試験の関係、運用後の見直しはIPAの[AI時代の要求管理ハンドブック](https://www.ipa.go.jp/digital/kaihatsu/youkyu-kanri.html)を参照する。
