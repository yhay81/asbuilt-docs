# 実装から開発資料を復元する

対象の版、読める資料、利用者が欲しい成果物を確認する。指定がなければ現在の版から進め、範囲を出力に添える。開発資料は日本語で書く。顧客の書式がある場合はその項目を優先する。

## 初回の復元

1. 入り口から実際の処理、設定、データ更新、例外時の戻り方まで追う。テストコードは何を確かめようとしているかの根拠に使い、実行結果は別に扱う。画面しか使えないときは、観察した条件と結果を記録する。
2. ソースから分かった現行動作と、業務で必要な振る舞いを別の項目にする。対象を誰が、なぜ、どの条件で承認したかは意思決定の記録を探す。資料が欠けていれば値を空け、確認すべき問いと確認先を添える。実装と社内規程が食い違うときは双方を示す。
3. [工程ごとの成果物](references/deliverables.md)から該当する資料と必須欄を選ぶ。対象外は理由を添える。利害関係者には普段の業務と例外を尋ね、コードに現れない要求も取り上げる。
4. 継続して使う案件では、[台帳の形式と使い方](references/ledger.md)に従い、一項目ずつ根拠の行、対象版、関連項目を記録する。`scripts/ledger.py`で参照を照合してからMarkdownを作る。個別の質問には、該当する根拠と結論を直接答えてよい。

## 変更後の確認

以前の台帳を読み、同じ仕様には同じ識別番号を使う。実装変更と、実装が同じまま業務ルールだけ変わった場合の両方を扱う。変更の根拠と承認者が分かる記録を追加し、影響する資料・再実行するテスト・未解決の相違を示す。新しい版での合否にはその版の実行記録を使う。人の回答や以前の結果を旧版に保ち、差分を確認して新版を作る。
